Installation

Clone the repository and install the project dependencies before starting the server. 


git clone https://github.com/your-org/EndPointGen.git

cd EndPointGen

npm install

Quick Start

Project Bootstrap

The startup process follows a predictable sequence, making debugging and maintenance easier.

1

Run server.js

The Node.js process starts from server.js.

2

Initialize app.js

Creates the Express application, loads middleware, and prepares routing.

3

Load Configuration

Reads project configuration using configLoader.js.

4

Register Routes

Registers all endpoint modules through the routing layer.

5

Accept Requests

The application is now ready to receive HTTP requests.

Request Lifecycle

Every request follows the same predictable processing pipeline.

① Incoming Request

A client sends an HTTP request to the Express server.

② Express Middleware

The request passes through registered middleware.

③ Route Resolution

Express matches the request to a registered endpoint.

④ Business Logic

The route handler executes application logic.

⑤ Response

JSON or another HTTP response is returned to the client.

Core File

app.js

The heart of EndPointGen. This module creates and configures the Express application before handing control to the HTTP server.

Purpose

Creates the Express application, loads middleware, registers routes, initializes configuration and exports the configured application instance.

Responsibilities

  • Create Express instance
  • Load configuration
  • Initialize middleware
  • Register routes
  • Export configured app

Typical Structure


import express from "express";
import loadConfig from "./configLoader.js";
import setupRoutes from "./routes.js";

const app = express();

loadConfig();

setupRoutes(app);

export default app;

Execution Order

Step Description
1 Create Express application
2 Load project configuration
3 Configure middleware
4 Register routes
5 Export application instance
Info

Keep app.js focused on application setup. Avoid putting business logic directly inside this file.

Core File

configLoader.js

Loads project configuration and validates settings before the application starts accepting requests.

Purpose

Centralizes configuration loading to keep startup predictable and maintainable.

Responsibilities

  • Load JSON configuration
  • Validate schema
  • Expose configuration
  • Prevent invalid startup

Example 


import { kschema } from "@keshavsoft/kschema";
import configJson from "./config.json";

export default function loadConfig() {

    kschema.loadConfig(configJson);

}

Configuration Lifecycle

  1. Read configuration
  2. Validate schema
  3. Load into memory
  4. Make configuration available
  5. Continue startup
Tip

Keep all project configuration in one place instead of hardcoding values throughout the application.

Core File

server.js

Application entry point responsible for creating the HTTP server and starting Express.

Purpose

Bootstraps the application and starts listening for incoming HTTP requests.

Responsibilities

  • Import app.js
  • Create HTTP server
  • Select listening port
  • Start application

Typical Structure 


import app from "./app.js";

const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {

    console.log(`Server running on ${PORT}`);

});

Startup Sequence

Stage Action
Import Load app.js
Initialize Create Express application
Listen Bind server port
Ready Accept HTTP requests
Best Practice

Avoid placing application configuration inside server.js. Keep this file responsible only for application startup.

Core File

routes.js

Central routing module responsible for registering all application routes.

Purpose

Collects every router module and attaches it to the Express application.

Responsibilities

  • Import routers
  • Register routers
  • Maintain routing hierarchy
  • Keep app.js clean

import express from "express";

import {
    router as routerFromBillsTable
} from "./BillsTable/end-points.js";

export default function setupRoutes(app){

    app.use(
        "/BillsTable",
        routerFromBillsTable
    );

}
Core File

appjs/routes.js

Defines application-level routing modules and organizes endpoint registration.

Module Responsibility

This file separates application routing from startup logic, improving maintainability.

Component Purpose
Express Router Creates modular routes
Imports Loads child routers
Export Provides router instance
Core File

startEndPoint/routes.js

Entry point responsible for registering the initial endpoint collection used by EndPointGen. 


router.use(
    "/BillsTable",
    routerFromBillsTable
);
Recommendation

Keep endpoint registration modular so new feature modules can be added without modifying application startup logic.

Frequently Asked Questions

Why use EndPointGen?

It provides a clean, modular approach to organizing Express.js endpoints and application startup.

Where should configuration be stored?

Keep configuration inside configLoader.js or dedicated configuration files.

Where should new endpoints be registered?

Register them inside the routing layer rather than directly in app.js.
